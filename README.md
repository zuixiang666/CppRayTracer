# CppRayTracer

这是一个基于 C++ 的光线追踪（Ray Tracing）渲染器。

本项目是我在**学习计算机图形学原理**的过程中，参考经典教程 **ssloy/tinyraytracer** 一步步手动敲写并复现的成果。在这个过程中，我不仅跑通了渲染流程，还独立解决了一些跨平台的兼容性问题，并对其进行了扩展。

## 致谢

## ✨ 目前实现的核心功能

- [x] **基础渲染管线**：将三维场景渲染为自定义二进制 PPM 格式图片。
- [x] **底层数学库封装**：自定义 `Vec3` 三维向量类，重载了基础运算符（加、减、点乘、标量乘、下标访问），并实现了向量归一化。
- [x] **碰撞检测**：实现射线与球体（Sphere）的相交检测，支持多球体的深度遮挡排序（Occlusion）。
- [x] **Phong 光照模型**：引入点光源与材质系统，实现了基于法线点乘的漫反射（Diffuse）与高光（Specular）计算。
- [x] **阴影（Shadows）**：通过向光源发射阴影射线（Shadow Rays）检测遮挡，并通过“阴影偏移（Shadow Offset）”技术完美解决自遮挡引起的“阴影痤疮”伪影。
- [x] **镜面反射（Reflection）**：实现递归光线追踪，支持完美的镜面反射材质，并设置了递归深度（Depth）防止栈溢出。
- [x] **抗锯齿（Anti-Aliasing）**：实现基于超采样（SSAA）的 4x4 多光线采样，并引入随机偏移量，极大平滑了物体边缘的锯齿。
- [x] **色调映射（Tone Mapping）**：在写文件前进行颜色截断与防过曝处理，保证高光区域的细节。

## 学习心得 / 踩坑记录
在复现本项目的过程中，我踩过以下几个坑，在此记录：
1. **文件流模式**：在 Windows 下使用 `std::ofstream` 写入二进制图片时，必须加上 `std::ios::binary`，否则换行符会被强制转换，导致图片乱码。
2. **射线方向**：计算光线方向向量后，必须进行**归一化（Normalize）**，否则会导致求交公式计算出错，屏幕全红。
3. **宽高比（Aspect Ratio）**：在将屏幕坐标映射到三维空间时，必须考虑屏幕的宽高比，否则渲染出的球体会变成椭圆。
4. **运算符重载**：在实现光照模型时，由于需要计算 `颜色向量 * 光照强度`，原有的 `Vec3f` 类只支持点乘（返回 float），不支持向量乘标量。通过阅读编译器报错，我手动在 `geometry.h` 中重载了 `operator* (const float &scalar)`，使其返回一个新的三维向量，成功解决了 `const Vec3f * float` 的编译错误。
5. **阴影伪影（Shadow Acne）**：通过判断法线与光源方向，将阴影射线起点沿法线方向偏移 `1e-3`，完美消除表面的黑色噪点。
